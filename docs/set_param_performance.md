# set_param 表达式的性能验证

本次扩展让非空运行期 override 使用对应类型宏已有的表达式解析器。Tcl 继续保存原文，
SV 在执行 `aip_int` / `aip_real` 等宏时抽样。这里测的是主机执行耗时，宏读取不推进仿真时间。

## 方法与范围

- 环境：VCS W-2024.09-SP1；基线为 `8067bcc`。
- 两个版本使用相同的 `test_set_param_benchmark.sv` 和 `cmdline_bench_clock.c`。
- 每项预热 100 次，再读取 20,000 次；同进程重复三个区间，每次重置 RNG，取中位数。
- 关闭参数打印，使用进程 CPU 时钟，同时记录单调墙钟和结果 checksum。
- 计时包含宏的查表、解析、抽样、task 调用和最小 checksum 累加；排除编译、许可证启动、
  表达式写入、预热、输出及 DUT。最终数据不能直接当作整个 UVM 环境的降速百分比。
- 旧版 override 不接受随机表达式，随机项以旧版 plusarg 为参照；不把旧版不支持的能力
  当作“零成本”。候选数量、文本长度、参数表大小、主机负载均可能影响实际结果。

## 固定值快速路径的原因

最初直接让固定 override 也走完整解析，单次初测的固定整数读取由约 10.92 µs 增至
22.37 µs，固定 real 由约 8.32 µs 增至 12.29 µs。这组数据只用于选择实现方式，
不是最终版本的三次中位数。

最终实现先做字符判别：无空白的数值字面量候选及不含分割符的普通字符串，沿用原来的
直接转换；正式转换仍负责完整校验。含空白的数字、范围、列表、权重、`inc/dec`、整数
`rand` 进入公共解析路径。固定值不构建候选数组或额外消费 RNG，随机结果每次重新抽样。
没有新增表达式缓存或结果缓存，更新/清除不需要额外的失效处理。

## 最终测量（2026-11-07）

固定 override 的 CPU 中位数如下，单位为 µs/次；括号是三个样本的最小值到最大值。

| 类型/输入 | 旧版 override | 新版 override | 中位数变化 |
|---|---:|---:|---:|
| int `200` | 10.99（10.89–11.88） | 12.08（11.93–12.83） | +9.9% |
| real `200.0` | 7.54（7.21–7.77） | 7.82（7.74–8.16） | +3.7% |

固定值仍有轻量判别成本。以每包读取一次、100 万包估算，固定 int 的这部分新增 CPU
约 1.09 秒，real 约 0.28 秒；不是总仿真耗时增加 9.9% 或 3.7%。实数样本区间有重叠，
这些百分比是本次观测值，不能当作所有环境下的稳定增幅。

随机表达式的 CPU 中位数如下，单位同为 µs/次：

| 类型/表达式 | 旧版 plusarg | 新版 plusarg | 新版 override |
|---|---:|---:|---:|
| int `[50:200]` | 56.76 | 51.23 | 50.62 |
| int `50,100,200` | 32.18 | 34.47 | 28.01 |
| int `{50:=20,[100:200]:/80}` | 99.30 | 100.76 | 95.97 |
| real `[50.0:200.0]` | 26.83 | 26.14 | 22.09 |
| real `50.0,100.0,200.0` | 23.97 | 23.74 | 20.12 |
| real `{50.0:=20,[100.0:200.0]:/80}` | 57.19 | 49.09 | 44.48 |

随机读取与既有 plusarg 解析处于同一量级；override 可省去 plusarg 查询的一部分工作。
本次没有优化原有随机解析算法，旧/新 plusarg 的观测差异可能受宿主机负载、代码生成等因素
影响，不能宣称它们全由本次代码变更带来。复杂权重比短列表更贵，逐包读取时应按实际字段数估算。

共完成 26 个来源/类型/表达式场景、78 个计时样本；同场景三个 repeat 的 checksum 一致，
相同随机表达式跨旧/新 plusarg 与新 override 的 checksum 也一致。
执行时生产文件 SHA256 为 `3d61e9dee0b8286b0e0faa9f45346131be1347c03bc13075b8876e72fbb42a8b`。
测试完成后的差异仅是生产文件头注释修正、基准源码 Tab/赋值列对齐，不改变执行逻辑。

## 功能验证

参考服务器上已通过 `make test_set_param_expressions` 和 `make test_cmdline_split_positive`：

- 33 个标量用例，每个来源各读取 64 次，相同 seed 的输出轨迹完全一致。
- 整数范围/列表/混合候选/权重/步长/`rand`、宽位整数、实数、字符串及枚举均覆盖。
- 数组、队列、schema 的来源一致性；优先级、运行期替换、清除、空值、raw getter 均覆盖。
- 12 种非法表达式分别经 plusarg 和 override 读取，共 24 次预期 fatal；检查非零退出和用户来源。
- 真实 Tcl 单项、块写法、括号保护和读取测试通过；固定数值/普通字符串的 RNG 状态保持检查通过。
- 既有 standalone/package 入口回归通过，包含 schema/queue 与诊断上下文清理。

## 如何复现单项

只在配置好 VCS 和许可证的仿真主机执行：

```bash
make bench_set_param_build
cd tests/sv
./simv_set_param_benchmark -no_save -exitstatus +ntb_random_seed=12345 \
    +BENCH_KIND=int +BENCH_SOURCE=override +BENCH_ITERS=20000 +BENCH_REPEATS=3 \
    '+bench.iv=[50:200]'
```

实数用 `+BENCH_KIND=real` 和 `+bench.rv=...`；来源改为 `plusarg` 即可测对应入口。
基线编译时复制同一份基准源码，不复制新版生产解析器。所有测量顺序执行，避免基准之间
争用 CPU。每个样本的 `cpu / reads × 1e6` 为 µs/次，`wall` 用来观察宿主机调度影响。

## 发包环境中的用法

固定配置在一批包开始时读取一次；需要逐包随机的字段在每包开始时读取一次。
例如每次读取耗时为 `C` µs，每包读取 `K` 个字段，发送 `N` 个包时，仅这一部分的粗略
CPU 成本为 `N × K × C / 1e6` 秒。它不包括报文构造、打包、driver、monitor 和 scoreboard。

Tcl 设置一次表达式后由 SV 重复抽样，避免每包往返 Tcl；包级配置无需在每个 beat 重新解析。
只读取原文再用 `$sscanf` 等自行转换的业务代码不会自动获得随机能力，需要在需要抽样的位置
使用对应类型入口。改变 rate 的抽样频率也需要由 sequence 明确定义。
